# TimeWork System Memory

อัปเดตล่าสุด: 4 กันยายน 2569

## สถานะที่ส่งมอบ

- Docker Compose รัน `api` และ `db` บน `aon@192.168.0.157`
- API health check ตอบ `200` ที่ `/health`
- โดเมน `timework.scriptbin.dev` เชื่อมถึง API ผ่าน Cloudflare Tunnel
- LINE webhook อยู่ที่ `/webhooks/line` และตรวจ HMAC SHA256 signature จาก `LINE_CHANNEL_SECRET`
- `LINE_CHANNEL_ACCESS_TOKEN` ถูกส่งเข้า API container แล้ว
- หน้า Dashboard ใช้ Bootstrap 5 จาก CDN เสิร์ฟจาก `public/index.html`
- Dashboard และ `/api` ทุกเส้นทางต้องยืนยันตัวตนด้วย `ADMIN_API_KEY` รับได้ทั้ง Basic auth และ header `x-admin-key` ยกเว้น `/health` และ `/webhooks/line`

## โครงสร้างข้อมูลปัจจุบัน

ตาราง `employees`

- `employee_code` รหัสพนักงานที่ไม่ซ้ำ
- `name` ชื่อพนักงาน
- `line_user_id` ใช้ผูกบัญชี LINE
- `active` สถานะใช้งาน
- `national_id` เลขที่บัตรประชาชน 13 หลัก มี unique partial index เฉพาะแถวที่ไม่เป็น NULL
- `phone` เบอร์โทร เก็บแบบตัดขีดและวรรคออกแล้ว
- `address` ที่อยู่
- `start_date` วันที่เริ่มงาน ชนิด DATE
- `ethnicity` เชื้อชาติ
- `shift_id` กะประจำ ใช้เมื่อยังไม่ตั้งตารางการทำงาน เป็น NULL ได้ หมายถึงไม่คิดสาย
- `employee_type_id` ประเภทพนักงาน เป็น NULL ได้
- `can_submit_expense` สิทธิ์ส่งรายการค่าใช้จ่ายผ่าน LINE ค่าเริ่มต้นปิด
- `department_id` แผนกหรือกลุ่มงาน เป็น NULL ได้

ตาราง `shifts`

- `name` ชื่อกะที่ไม่ซ้ำ
- `start_time` และ `end_time` ชนิด TIME กะข้ามคืนใส่เวลาออกน้อยกว่าเวลาเข้าได้
- `grace_minutes` เวลาอนุโลมสาย 0 ถึง 240 นาที
- `break_minutes` เวลาพัก 0 ถึง 480 นาที ค่าเริ่มต้น 60 ใช้หักออกจากเวลาทำงานในรายงาน
- `active` สถานะใช้งาน

ตาราง `time_logs`

- `employee_id` อ้างอิงพนักงาน
- `event_type` เป็น `check_in` หรือ `check_out`
- `occurred_at` เวลาบันทึก
- `source` เป็น `line` เมื่อสแกนผ่านแชท `liff` เมื่อลงเวลาผ่านหน้า LIFF พร้อมพิกัด และ `manual` เมื่อผู้ดูแลเติมย้อนหลัง
- `latitude` `longitude` `accuracy_m` `location_address` เก็บพิกัดตอนลงเวลา มีค่าเฉพาะที่มาจาก LIFF
- `note` หมายเหตุ

ตาราง `schedule_weekly` ตารางประจำสัปดาห์

- คีย์หลักคือ `employee_id` กับ `weekday` โดย `weekday` ใช้เลขเดียวกับ `EXTRACT(DOW)` คือ 0 = อาทิตย์ ถึง 6 = เสาร์
- `shift_id` เป็น NULL หมายถึงวันหยุดตามตาราง
- API เขียนครบทั้ง 7 วันเสมอ จึงใช้ `EXISTS` เพื่อรู้ว่าพนักงานคนนั้นตั้งตารางไว้หรือยัง

ตาราง `work_sites` สถานที่ทำงานที่อนุญาต

- `name` ไม่ซ้ำ `latitude` `longitude` เป็น NUMERIC(9,6) และ `radius_m` 20 ถึง 20000 เมตร
- ถ้าไม่มีแถวที่ `active` ระบบจะเก็บพิกัดไว้แต่ไม่ตรวจว่าอยู่ในพื้นที่หรือไม่

ตาราง `departments` แผนกหรือกลุ่มงาน

- `name` ชื่อแผนกที่ไม่ซ้ำ ยาวได้ 120 ตัวอักษร
- `note` และ `active` สำหรับหมายเหตุและสถานะใช้งาน

ตาราง `employee_types` ประเภทพนักงาน

- `name` ชื่อประเภทที่ไม่ซ้ำ
- `pay_type` เป็น `daily` หรือ `monthly` เท่านั้น มี CHECK ในฐานข้อมูล
- `pay_rate` เป็น NUMERIC(12,2) อ่านออกมาเป็น float8 เพื่อให้ JSON เป็นตัวเลขไม่ใช่สตริง
- `active` สถานะใช้งาน
- กฎคำนวณค่าจ้างเก็บที่ประเภท ไม่ฝังในโค้ด ได้แก่ `ot_multiplier` ค่าเริ่มต้น 1.5 เท่า `late_deduct_per_minute` ค่าเริ่มต้น 0 `monthly_days_divisor` ค่าเริ่มต้น 30 และ `work_hours_per_day` ค่าเริ่มต้น 8

ตาราง `payroll_entries` การเบิกและการจ่ายเงิน

- `kind` เป็น `advance` การเบิกล่วงหน้า หรือ `payment` การจ่ายเงิน มี CHECK ในฐานข้อมูล
- `amount` ต้องมากกว่า 0 และไม่เกิน 10,000,000
- `entry_date` ใช้จับว่ารายการอยู่ในช่วงคำนวณไหน

ตาราง `expense_claims` รายการค่าใช้จ่ายที่พนักงานส่งเข้ามา

- `status` เป็น `pending` `approved` หรือ `rejected` มี CHECK ในฐานข้อมูล
- `approved_amount` ใส่เมื่ออนุมัติ แก้ให้น้อยกว่ายอดที่ขอได้ ตอนไม่อนุมัติจะถูกล้างเป็น NULL
- `review_note` เหตุผลของผู้ตรวจ พนักงานเห็นในหน้าของตัวเอง
- ยอดที่อนุมัติ **ยังไม่ถูกนำไปรวมกับค่าจ้างอัตโนมัติ** ถ้าจะจ่ายคืนต้องบันทึกเป็น payroll_entries kind payment เอง

ตาราง `ot_approvals` การอนุมัติ OT รายวัน

- คีย์หลักคือ `employee_id` กับ `work_date` มีแถว = อนุมัติแล้ว ไม่มีแถว = ไม่จ่ายเงิน OT ของวันนั้น
- `approved_minutes` เป็น NULL หมายถึงอนุมัติเท่าที่ระบบคำนวณได้ ใส่เลขเพื่ออนุมัติบางส่วน
- `approved_minutes = 0` คือ **ไม่อนุมัติ** ตรวจแล้วและไม่จ่าย ต่างจากไม่มีแถวเลยซึ่งหมายถึงยังไม่ได้ตัดสินใจ ทั้งสองกรณีจ่าย 0 แต่แยกกันเพื่อรู้ว่าตรวจครบแล้วหรือยัง
- `note` เก็บเหตุผลการอนุมัติ

ตาราง `leaves` การลา

- คีย์หลักคือ `employee_id` กับ `work_date` 1 แถวต่อคนต่อวัน
- `leave_type` ตรวจกับรายการคงที่ `LEAVE_TYPES` ในโค้ด ลาป่วย ลากิจ ลาพักผ่อน ลาคลอด ลาสลับวันหยุด ลาไม่รับค่าจ้าง
- วันที่ลาจะไม่คิดสายและไม่นับขาดงานในรายงาน

ตาราง `schedule_overrides` ตารางรายวันที่

- คีย์หลักคือ `employee_id` กับ `work_date`
- `shift_id` เป็น NULL หมายถึงวันหยุดเฉพาะวันนั้น
- `note` ใช้บันทึกเหตุผล เช่น สลับเวร หรือหยุดชดเชย

## ข้อควรระวังเชิงเทคนิค

- Webhook ต้องใช้ request body ดิบในการตรวจ signature ห้ามเปลี่ยน parser JSON โดยไม่คง raw body ไว้
- LINE จะเรียก webhook ด้วย POST เท่านั้น ดังนั้น GET `/webhooks/line` ที่ได้ 404 เป็นพฤติกรรมปกติ
- คำสั่งลงเวลาใน Bot ป้องกันการลงเวลาเข้าและออกซ้ำภายในวันเดียวกันตามเวลาเซิร์ฟเวอร์
- auth hook ถูก register ก่อน `@fastify/static` โดยเจตนา เพราะ Fastify ส่งต่อ hook ให้ปลั๊กอินที่ register หลังจากนั้นเท่านั้น ถ้าย้ายไปไว้ทีหลัง หน้า Dashboard จะหลุดการป้องกัน
- auth เป็นแบบ fail closed ถ้าไม่ได้ตั้ง `ADMIN_API_KEY` ระบบจะตอบ 503 ทุกเส้นทางของผู้ดูแล ไม่ปล่อยผ่าน
- เลขที่บัตรประชาชนถูกตรวจ check digit หลักที่ 13 ตามสูตรของกรมการปกครอง ถ้าพิมพ์ผิดจะถูกปฏิเสธด้วย HTTP 400 พนักงานต่างชาติที่ไม่มีบัตรประชาชนไทยให้เว้นช่องนี้ว่างไว้
- `start_date` อ่านออกมาเป็นสตริงด้วย `to_char(start_date,'YYYY-MM-DD')` เพื่อไม่ให้ timezone ทำให้วันเลื่อน และใช้กับ `<input type="date">` ได้ตรงๆ
- คอลัมน์ที่ PATCH เขียนได้มาจากรายการคงที่ในโค้ด ไม่ใช่ key ที่ผู้ใช้ส่งมา จึงไม่เปิดช่อง SQL injection
- ตารางรายชื่อพนักงานบนหน้าเว็บไม่แสดงเลขที่บัตรประชาชนและ LINE User ID จะเห็นได้เฉพาะเมื่อเปิดหน้ารายละเอียดรายคน
- การคิดสายใช้สูตรใน `lateMinutesSql()` คือแปลง `occurred_at` เป็นเวลาไทยก่อน แล้วลบ `start_time` และหัก `grace_minutes` ผลลัพธ์ติดลบถูกปรับเป็น 0 ด้วย `GREATEST`
- `late_minutes` เป็น NULL เมื่อเป็นการลงเวลาออก หรือพนักงานยังไม่ได้กำหนดกะ หน้าเว็บจึงแสดงเป็นขีด ไม่ใช่ ตรงเวลา
- ข้อจำกัดของกะข้ามคืน ถ้าพนักงานกะ 22:00 ลงเวลาเข้าหลังเที่ยงคืน เช่น 01:00 การลบเวลาจะได้ค่าติดลบและถูกปรับเป็น 0 จึงนับว่าตรงเวลา ถ้าต้องคิดสายกรณีนี้ให้จริงจังต้องเก็บวันที่ของกะแยกจากเวลาที่ลง
- ระบบใหม่จะได้กะเริ่มต้นชื่อ `กะปกติ` 08:00 ถึง 17:00 อนุโลม 15 นาที โดย `initializeDatabase()` จะเพิ่มให้เฉพาะตอนที่ตาราง `shifts` ยังว่าง
- ลำดับการหากะที่ต้องใช้ในวันหนึ่งอยู่ใน `scheduleSourceSql()` คือ ตารางรายวันที่ ก่อน ตารางประจำสัปดาห์ ก่อน `employees.shift_id` โค้ดที่ต้องรู้กะของวันใดต้องเรียกผ่านฟังก์ชันนี้ ห้าม join `employees.shift_id` ตรงๆ เพราะจะข้ามตาราง
